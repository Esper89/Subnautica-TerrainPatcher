Terrain Patch Format (v0)

This is the format specification for version 0 of the Subnautica terrain patch format, the first version. For general information and important context, see the main specification for the patch format.

Format

File

Byte 0 1 2 3 …
Field Version Batches
Type uint Batch[]

Each patch file starts with an unsigned 32-bit integer that encodes the format version; this specification is for version 0. After this, the patch contains an array of any number of batches, which can be either modified batches that need to be patched or new batches that need to be created. The number of batches is determined by the size of the file.

Batch

Byte 0 1 2 3 4 5 6 …
Field X Y Z Octree Count Octrees
Type short short short byte Octree[]

Batches start with three signed 16-bit integers indicating the X, Y, and Z coordinates of the batch. In the game's terrain format, these fields are the three numbers in the name of the batch, compiled-batch-X-Y-Z.optoctrees. The coordinates of the batch are followed by a single unsigned 8-bit integer representing the number of octrees in the batch that need to be replaced or created. The rest of the batch is an array of that many octrees.

Octree

Byte 0 1 2 …
Field Octree Index Node Count Nodes
Type byte ushort Node[]

Each octree begins with a single unsigned 8-bit integer indicating the index of this octree in the final batch, from 0 to 124, as specified in the game's terrain format. Next is an unsigned 16-bit integer representing the number of nodes in this octree, followed by an array of that many nodes; this part is identical to the game's terrain format.

Node

Byte 0 1 2 3
Field Material Type Signed Distance Child Index
Type byte byte ushort

Nodes themselves are identical to the game's terrain format.

Example Data

00000000 0C00 1200 0C00 03 00 0100 00000000 01 0100 00000000 02 0100 00000000 0000 0000 0000 01 7C 0100 23000000 FEFE 1300 FCFF 02 23 0100 01000000 4C 0100 01000000 1C00 1300 1C00 02 64 0100 23000000 03 0100 23000000

This example terrain patch replaces the first three octrees in the batch at (12, 18, 12) with single-node empty octrees, replaces the last octree in batch (0, 0, 0) with a single-node octree of material #23, creates a new batch at (−2, 19, −4) with two single-node octrees of material #1, and creates a new batch at (28, 19, 28) with two single-node octrees of material #23.

Explanation

The format version number is 00 00 00 00.

The first batch to modify is at position 0C 00 12 00 0C 00 (12, 18, 12) and replaces 03 octrees. The first octree is at index 00 and contains 01 00 node. The node's data is 00 00 00 00. The other two octrees are the same, except their indices are 01 and 02.

The second batch to modify is at position 00 00 00 00 00 00 and replaces 01 octree. That octree is at index 7C (124) and contains 01 00 node. The node's data is 23 00 00 00.

The third batch to create is at position FE FF 13 00 FC FF (−2, 19, −4) and contains 02 octrees. The first octree is at index 23 (35) and contains 01 00 node. The node's data is 01 00 00 00. The second octree is the same, except its index is 4C (76).

The third batch to create is at position 1C 00 13 00 1C 00 (28, 19, 28) and contains 02 octrees. The first octree is at index 64 (100) and contains 01 00 node. The node's data is 23 00 00 00. The second octree is the same, except its index is 03.

As you can see from this example, terrain patches create new batches the same way they patch existing batches. Batches can be created outside the world bounds, including at negative locations.
